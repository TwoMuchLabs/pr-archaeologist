## Decision records

- **[ADR-0001: Record architecture decisions](docs/adr/0001-record-architecture-decisions.md)** — _Accepted_ (2019-05-20)
  - Decision: We will record significant decisions as short ADRs in `docs/adr`.
  - Consequences: A change that contradicts an ADR needs a new ADR that supersedes it.
- **[ADR-0002: Idempotency keys on every gateway write](docs/adr/0002-idempotency-keys.md)** — _Accepted_ (2019-06-25)
  - Decision: Every write to the gateway carries an `Idempotency-Key` header generated by `payments/idempotency.py`. The key is derived from the logical charge, never from the attempt.
  - Consequences: Retries are safe only while the key is stable. Anything that changes how the key is built, or calls `payments/gateway.py` without one, can double-charge customers again.
  - Governs: `payments/gateway.py`, `payments/idempotency.py`, `payments/retry.py`
- **[ADR-0003: Money is integer minor units](docs/adr/0003-integer-minor-units.md)** — _Accepted_ (2020-02-24)
  - Decision: All amounts are stored and computed as integer minor units. Conversion happens once, at the API boundary, in `payments/currency.py`.
  - Consequences: Never introduce a float amount into `payments/ledger.py`. Currencies without minor units (JPY) must go through the `MINOR_UNITS` table.
  - Governs: `api/handlers.py`, `payments/currency.py`, `payments/ledger.py`

  - [fix] 2023-05-09 `82b8ab0` race between webhook and retry loop recording a charge twice — The webhook and the retry loop could both write the same charge to the ledger.
  - [warning] 2023-05-09 `82b8ab0` Always use record_once() for charges; record() is for manual adjustments only.
  - [fix] 2024-03-18 `24c3d32` cap backoff at 30s so workers do not stall — Uncapped exponential backoff reached 17 minutes during the March gateway outage and starved the queue.
